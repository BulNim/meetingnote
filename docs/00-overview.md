# 00. Overview

**MeetingNote - 회의록 자동 정리 풀스택 웹 앱**

## 문서 매핑표

| 파일명 | 역할 | 알 수 있는 것 |
|---|---|---|
| `00-overview.md` | 전체 안내 | 프로젝트 개요, 문서 구성, 읽는 순서, 화면 종류, 문서를 나눈 이유 |
| `01-product.md` | 제품 정의 | 무엇을, 누구를 위해, 왜 만드는지 |
| `02-specs.md` | 기능 명세 | 기능별 동작 규칙, API, 데이터 구조 |
| `03-design.md` | 설계 | 화면 설계, 백엔드·프론트 구조, 데이터 흐름 |
| `04-tasks.md` | 작업 목록 | 해야 할 일, 진행 순서, 완료 기준 |
| `05-conventions.md` | 코딩 규칙 | 네이밍, 코드 스타일, 테스트 작성 규칙 |

## 읽는 순서

`00` > `01` > `02` > `03` > `04` > `05`

## 화면

화면은 목록 · 넣기 · 상세 · 할 일 4종이다.
배치와 요소 이름은 `docs/화면구성.pdf` 를 따른다. id 는 그 파일에 적힌 그대로 쓴다.

- 디자인: UI 는 맥OS 스타일로 한다. CSS 라이브러리는 Tailwind 를 쓰고, 깔끔하고 모던하게 만든다.

## 왜 이렇게 나누는가

관심사 분리(separation of concerns) 원칙에 따라 문서를 나눈다. 한 문서는 한 가지 질문에만 답한다.

- 무엇을 만드는가: `01-product.md`
- 어떻게 동작해야 하는가: `02-specs.md`
- 어떻게 짜는가: `03-design.md`
- 무엇을 할 것인가: `04-tasks.md`
- 어떤 규칙으로 쓰는가: `05-conventions.md`

이렇게 나누면 바뀌는 이유가 다른 내용이 한 곳에 섞이지 않는다. 기능이 바뀌면 `02` 만, 코딩 규칙이 바뀌면 `05` 만 고친다. 지시와 문서가 어긋날 때도 문서명과 조항을 짚어 바로 확인할 수 있다.
