# 03. Design

| 항목 | 선택 | 대안 | 근거 | 트레이드오프 |
|---|---|---|---|---|
| 1) 백엔드 | FastAPI | Django, Express | Python 3.11 이상 + Pydantic 검증이 기본 제공되고, 라우트가 얇아 7개 API 에 알맞다. | Django 처럼 관리자 화면·인증이 기본으로 따라오지 않아 필요하면 직접 붙인다. |
| 2) 프론트 | Vanilla JS + Tailwind CDN. `index.html` 과 `app.js` 2개 파일만 둔다. 백엔드가 같은 오리진에서 제공하며 `file://` 로 직접 열지 않는다. | React, Vue | 화면이 4종뿐이라 빌드 도구 없이 충분하다. 같은 오리진이라 CORS 설정이 필요 없다. | 컴포넌트 재사용이 약하다. 화면이 늘면 `app.js` 가 커져 구조 관리가 어렵다. |
| 3) DB | SQLite (SQLAlchemy ORM, 추후 PostgreSQL 전환 고려) | PostgreSQL 즉시 도입 | 파일 하나로 끝나 실습 환경 설치가 없다. ORM 을 거치므로 전환 때 모델 수정이 작다. | 동시 쓰기에 약하다. 전환 때 SQLite 전용 설정(`sqlite_autoincrement`)을 걷어내야 한다. |
| 4) CSS | Tailwind 만 쓴다. styled-components 금지. | styled-components, 직접 작성한 CSS 파일 | 스타일 방식을 하나로 고정해 어디서 고칠지 헷갈리지 않는다. 빌드가 필요 없다. | CDN 방식이라 HTML 클래스가 길어진다. 오프라인에서는 스타일이 적용되지 않는다. |
| 5) 받아쓰기 | Gemini API (`gemini-3.1-flash-lite`). 키는 `.env` 로만 읽고 저장소에 올리지 않는다. | Whisper 자체 구동, 브라우저 음성 인식 | 서버에 모델을 올릴 필요가 없고, 받아쓰기와 세 갈래 구분을 같은 API 로 처리한다. | 외부 호출에 의존한다. 실패하면 502 이고 비용·호출 한도가 생긴다. |
| 6) 상태관리 | 모듈 변수 + DOM 직접 갱신 | 상태관리 라이브러리, 가상 DOM | 상태가 목록·모달·테마 정도라 별도 도구가 필요 없다. | 상태가 늘면 갱신 누락이 생기기 쉽다. 화면 갱신 함수를 한곳에 모아 둔다. |
| 7) 디자인 시스템 | Mac OS UI 톤(둥근 모서리, 부드러운 그림자, 반투명 카드, 시스템 폰트). 화면 배치는 `docs/화면구성.pdf` 를 따르고, 요소 id 는 그 5쪽 표를 그대로 옮긴다: `q`·`from`·`to` / `cards` / `title`·`metAt`·`attendees` / `file`·`body` / `btnUp`·`btnSave` / `result` / `modal` / `mTitle` / `todoBody`. 한 번 정하면 바꾸지 않고, 바꿔야 하면 사유를 먼저 적는다. | Material, Ant | 요구한 톤과 맞고, Tailwind 만으로 만들 수 있다. id 를 고정하면 화면을 다시 만들어도 `app.js` 와 테스트가 깨지지 않는다. | 외부 컴포넌트 라이브러리의 완성된 부품을 쓰지 못하고 직접 만든다. |
| 8) 테마 | 라이트/다크 토글. `localStorage` 에 저장하고, 초기값은 시스템 설정을 따른다. | 라이트 고정, 서버에 저장 | 사용자 설정을 서버 없이 유지한다. 처음 접속해도 시스템 설정에 맞는다. | 브라우저·기기가 다르면 설정이 공유되지 않는다. |
