# 02 - Specs (WHAT)

## Meeting 모델 필드 8개 (이 순서, 이 타입)

| # | 필드 | 타입 | 설명 |
|---|---|---|---|
| 1 | `id` | INTEGER, PK, AUTOINCREMENT | |
| 2 | `title` | VARCHAR(200) | 필수 |
| 3 | `met_at` | DATETIME (UTC) | 필수. 회의를 한 시각 |
| 4 | `attendees` | TEXT | 쉼표로 구분 |
| 5 | `body` | TEXT | 필수. 받아쓴 원문 또는 붙여넣은 메모 |
| 6 | `summary` | TEXT | |
| 7 | `decisions` | TEXT | |
| 8 | `todos` | TEXT | |

- 세 갈래 결과(`summary` · `decisions` · `todos`)는 각각 줄바꿈으로 구분해 저장한다
- `todos` 는 한 줄에 하나씩 `내용 | 담당자 | 기한` 형식으로 저장한다

## 세 갈래를 나누는 기준 (이대로 프롬프트에 넣을 것)

- **요약** - 회의 전체를 3~5줄로. 새로운 사실을 지어내지 말 것
- **결정사항** - 「하기로 했다 / 확정 / 승인」 처럼 합의가 끝난 것만.
  논의만 하고 안 정한 것은 넣지 말 것
- **할 일** - 담당자와 기한이 드러난 것만. 담당자가 없으면 `미정` 으로 적을 것
- 셋 중 어디에도 안 들어가는 잡담은 버릴 것

## 검증

- `title` / `met_at` / `body` 없으면 **400**
- 없는 id 는 **404**
- FastAPI 기본은 422 이므로, 검증 실패를 400 으로 바꾸는 예외 핸들러를 둔다.
  스펙 외 필드만 **422** 로 남긴다
- 스펙 외 필드를 걸러내려면 Pydantic 모델에 `extra=forbid` 를 준다.
  기본값으로 두면 모르는 필드가 조용히 무시되어 201 이 나온다
- 업로드 파일이 mp3, wav 가 아니면 **415**
- 25MB 초과면 **413**
- `met_at` 은 UTC 로 저장한다. 화면의 `datetime-local` 값은 로컬 시각이므로
  보낼 때 UTC 로 바꾸고, 받아서 표시할 때 로컬로 되돌린다

## REST API 7개 (경로는 `/api/` 접두사 필수)

| # | 메서드 · 경로 | 성공 | 하는 일 |
|---|---|---|---|
| 1 | `POST /api/notes` | 201 | 저장하며 세 갈래 구분까지 |
| 2 | `GET /api/notes` | 200 | 목록 (`q` 로 제목 · 참석자 검색, `from` · `to` 로 날짜) |
| 3 | `GET /api/notes/{id}` | 200 | 단건 |
| 4 | `PUT /api/notes/{id}` | 200 | 수정 |
| 5 | `DELETE /api/notes/{id}` | 204 | 삭제 |
| 6 | `GET /api/todos` | 200 | 할 일만 모아 보기. 응답 필드 `what` / `who` / `when` / `note_id` / `note_title` |
| 7 | `POST /api/upload` | 200 | 녹취 파일을 받아 본문 텍스트로 반환 |

- 목록엔 `body` 제외, 단건은 포함

## 검색 규칙

- `q` 는 제목과 참석자에 대한 부분 일치. 본문은 검색하지 않는다
- `from`, `to` 는 `YYYY-MM-DD` 이고 양끝을 포함한다. `to` 는 그날 23:59:59 까지

## 기한 처리

`todos` 의 기한은 회의에서 말한 그대로 둔다 (「다음 주 금요일」 같은 자유 문구).
날짜로 바꾸지 않는다. 기한으로 정렬하거나 거르는 기능도 만들지 않는다.

## 실패 처리

- 받아쓰기나 구분이 실패하면 저장은 그대로 **201** 로 하고
  `summary`, `decisions`, `todos` 를 빈 값으로 둔다.
  화면에는 「구분 실패」로 표시하고, 서버는 `logging` 으로만 남긴다
- `POST /api/upload` 가 외부 호출에서 실패하면 **502**

## 화면 명세

화면은 4종이다.

1. 목록
2. 넣기
3. 상세
4. 할 일

배치와 요소 이름은 `03-design.md` 에서 정한다.

### 넣기 화면 - 저장 뒤 처리

- 저장(201)에 성공하면 넣기 화면의 입력칸(`title` · `metAt` · `attendees` ·
  `file` · `body`)을 모두 비운다. 결과 세 칸(`result`)만 남긴다
- 저장이 끝날 때까지 `btnSave` 를 잠근다. 응답이 오기 전에 다시 눌러도 요청이
  두 번 나가지 않게 한다
- 서버는 같은 내용이 다시 와도 201 로 저장한다. 중복은 화면에서 막는다

### 써 보고 나온 동작 결함

| 발견 | 증상 | 처리 |
|---|---|---|
