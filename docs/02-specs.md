# 02. 기능 명세

> 이 문서의 내용은 **고정**이다. 바꾸려면 먼저 이 문서를 고친다.

## 1. 데이터 모델 - Meeting

필드 8개. **이 순서, 이 타입 그대로** 만든다.

| # | 필드 | 타입 | 필수 | 설명 |
|---|---|---|---|---|
| 1 | `id` | INTEGER, PK, AUTOINCREMENT | - | 자동 증가 |
| 2 | `title` | VARCHAR(200) | 필수 | 회의 제목 |
| 3 | `met_at` | DATETIME (UTC) | 필수 | 회의를 한 시각 |
| 4 | `attendees` | TEXT | | 참석자. 쉼표로 구분 |
| 5 | `body` | TEXT | 필수 | 받아쓴 원문 또는 붙여넣은 메모 |
| 6 | `summary` | TEXT | | 요약 |
| 7 | `decisions` | TEXT | | 결정사항 |
| 8 | `todos` | TEXT | | 할 일 |

### 1.1 AUTOINCREMENT

- SQLite 는 PK 만 주면 **지운 id 를 다시 쓴다.** 테이블에 `AUTOINCREMENT` 가 **실제로** 들어가게 한다.
- SQLAlchemy 면 테이블에 `sqlite_autoincrement=True` 를 준다.

### 1.2 세 갈래 저장 형식

- `summary` · `decisions` · `todos` 는 각각 **줄바꿈으로 구분**해 저장한다.
- `todos` 는 **한 줄에 하나씩**, 다음 형식으로 저장한다.

  ```
  내용 | 담당자 | 기한
  ```

## 2. 세 갈래를 나누는 기준

아래 기준을 **이대로 프롬프트에 넣는다.**

| 갈래 | 기준 |
|---|---|
| 요약 | 회의 전체를 3~5줄로. 새로운 사실을 지어내지 말 것 |
| 결정사항 | 「하기로 했다 / 확정 / 승인」 처럼 합의가 끝난 것만. 논의만 하고 안 정한 것은 넣지 말 것 |
| 할 일 | 담당자와 기한이 드러난 것만. 담당자가 없으면 `미정` 으로 적을 것 |
| (버림) | 셋 중 어디에도 안 들어가는 잡담은 버릴 것 |

### 2.1 할 일의 기한

- 기한은 **회의에서 말한 그대로** 둔다 (예: `다음 주 금요일` 같은 자유 문구).
- 날짜로 바꾸지 않는다.
- 기한으로 **정렬하거나 거르는 기능을 만들지 않는다.**

## 3. REST API

경로는 모두 **`/api/` 접두사 필수**. 7개.

| # | 메서드 | 경로 | 성공 | 설명 |
|---|---|---|---|---|
| 1 | POST | `/api/notes` | 201 | 저장하며 세 갈래 구분까지 |
| 2 | GET | `/api/notes` | 200 | 목록. `q` 로 제목·참석자 검색, `from` · `to` 로 날짜 |
| 3 | GET | `/api/notes/{id}` | 200 | 단건 |
| 4 | PUT | `/api/notes/{id}` | 200 | 수정 |
| 5 | DELETE | `/api/notes/{id}` | 204 | 삭제 |
| 6 | GET | `/api/todos` | 200 | 할 일만 모아 보기 |
| 7 | POST | `/api/upload` | 200 | 녹취 파일을 받아 본문 텍스트로 반환 |

### 3.1 응답 필드

- **목록**(`GET /api/notes`)에는 `body` 를 **제외**한다. **단건**(`GET /api/notes/{id}`)은 **포함**한다.
- **할 일**(`GET /api/todos`)의 응답 필드:

  | 필드 | 뜻 |
  |---|---|
  | `what` | 할 일 내용 |
  | `who` | 담당자 |
  | `when` | 기한 (회의에서 말한 그대로) |
  | `note_id` | 회의록 id |
  | `note_title` | 회의록 제목 |

  정렬은 **회의 날짜(`met_at`) 오래된 순**.

## 4. 검증과 오류 코드

| 상황 | 코드 |
|---|---|
| `title` / `met_at` / `body` 가 없음 | **400** |
| 없는 id | **404** |
| 스펙 외 필드가 들어옴 | **422** |
| 업로드 파일이 mp3, wav 가 아님 | **415** |
| 업로드 파일이 25MB 초과 | **413** |
| `POST /api/upload` 의 외부 호출 실패 | **502** |

### 4.1 400 과 422 를 가르는 법

- FastAPI 기본은 검증 실패를 **422** 로 낸다. 검증 실패를 **400** 으로 바꾸는 **예외 핸들러**를 둔다.
- **스펙 외 필드만 422** 로 남긴다.
- 스펙 외 필드를 걸러내려면 Pydantic 모델에 **`extra="forbid"`** 를 준다.
  기본값으로 두면 모르는 필드가 조용히 무시되어 **201 이 나온다.**

## 5. 시각 (met_at) - UTC

- `met_at` 은 **UTC 로 저장**한다.
- 화면의 `datetime-local` 값은 **로컬 시각**이다.
  - 보낼 때: 로컬 → **UTC** 로 바꾼다
  - 받아서 표시할 때: UTC → **로컬** 로 되돌린다

## 6. 검색 규칙

- `q` : **제목과 참석자**에 대한 **부분 일치**. **본문은 검색하지 않는다.**
- `from` · `to` : `YYYY-MM-DD`. **양끝을 포함**한다. `to` 는 그날 **23:59:59 까지**.
- `from` · `to` 는 **화면의 로컬 날짜 기준**이다.

## 7. 실패 처리

### 7.1 구분 실패 (POST /api/notes)

- 받아쓰기나 구분이 실패해도 **저장은 그대로 201** 로 한다.
  `summary` · `decisions` · `todos` 는 **빈 값**으로 둔다.
- 화면에는 **구분 실패**로 표시한다.
- 서버는 **`logging` 으로만** 남긴다.
- 본문이 **회의 내용이 아니면** 세 칸을 빈 값으로 둔다.
- 본문이 **20자 미만**이면 구분을 **부르지 않고** 세 칸을 빈 값으로 둔다.

### 7.2 받아쓰기 실패 (POST /api/upload)

- 외부 호출이 실패하면 **502**.

### 7.3 재시도

- Gemini 가 **429 · 503** 이면 잠시 뒤 **1번 다시** 부른다.
