# 기능·기술 명세

## Meeting 모델

| 순서 | 필드 | 타입 | 제약·설명 |
|---:|---|---|---|
| 1 | `id` | `INTEGER, PK, AUTOINCREMENT` | 기본 키 |
| 2 | `title` | `VARCHAR 200, 필수` | 회의 제목 |
| 3 | `met_at` | `DATETIME UTC, 필수` | 회의를 한 시각 |
| 4 | `attendees` | `TEXT, 쉼표로 구분` | 참석자 목록 |
| 5 | `body` | `TEXT, 필수` | 받아쓴 원문 또는 붙여넣은 메모 |
| 6 | `summary` | `TEXT` | 요약 결과 |
| 7 | `decisions` | `TEXT` | 결정사항 결과 |
| 8 | `todos` | `TEXT` | 할 일 결과 |

세 갈래 결과는 각각 줄바꿈으로 구분해 저장한다.

`todos`는 한 줄에 하나씩 `내용| 담당자| 기한` 형식으로 저장한다.

## 세 갈래를 나누는 기준

다음 기준을 그대로 프롬프트에 넣는다.

- 요약 - 회의 전체를 3~5줄로. 새로운 사실을 지어내지 말 것
- 결정사항 - 「하기로 했다/ 확정/ 승인」처럼 합의가 끝난 것만
- 논의만 하고 안 정한 것은 넣지 말 것
- 할 일 - 담당자와 기한이 드러난 것만. 담당자가 없으면 미정으로 적을 것

## 검증

- `title`, `met_at`, `body`가 없으면 `400`
- 없는 `id`는 `404`
- FastAPI 기본 검증 오류 상태 코드는 `422`이므로 검증 실패를 `400`으로 바꾸는 예외 핸들러를 둔다.
- 스펙 외 필드만 `422`로 남긴다.
- 스펙 외 필드를 걸러내려면 Pydantic 모델에 `extra=forbid`를 준다.
- `extra=forbid`를 기본값으로 두면 모르는 필드가 조용히 무시되어 `201`이 나오는 문제가 있으므로 사용하지 않는다.
- 업로드 파일이 `mp3`, `wav`가 아니면 `415`
- 25MB 초과면 `413`
- `met_at`은 UTC로 저장한다.
- 화면의 `datetime-local` 값은 로컬 시각이므로 보낼 때 UTC로 바꾸고, 받아서 표시할 때 로컬로 되돌린다.

## REST API

모든 경로에 `/api/` 접두사를 필수로 사용한다.

| 메서드 | 경로 | 성공 상태 | 설명 |
|---|---|---:|---|
| `POST` | `/api/notes` | `201` | 회의록 저장 및 세 갈래 구분 |
| `GET` | `/api/notes` | `200` | 목록 조회. `q`로 제목·참석자 검색, `from`·`to`로 날짜 검색 |
| `PUT` | `/api/notes/{id}` | `200` | 회의록 수정 |
| `DELETE` | `/api/notes/{id}` | `204` | 회의록 삭제 |
| `GET` | `/api/todos` | `200` | 할 일만 모아 보기 |
| `POST` | `/api/upload` | `200` | 녹취 파일을 받아 본문 텍스트로 반환 |

`GET /api/todos` 응답 필드:

- `what`
- `who`
- `when`
- `note_id`
- `note_title`

목록 응답에는 `body`를 제외하고, 단건 응답에는 `body`를 포함한다.

## 화면 명세 기준

화면 명세는 `실습소재/화면구성.pdf`를 기준으로 한다. 화면을 만들 때 해당 파일을 직접 확인한다.

화면 4종:

1. 목록
2. 넣기
3. 상세
4. 할 일

화면을 사용해 보고 확인한 동작 결함은 이 문서에 기록한다.
