# 04. 작업 목록

MVP 를 **3개 Phase** 로 진행한다. **Phase 이름과 개수는 아래 3개 그대로 고정. 변경 금지.**

| Phase | 이름 | 범위 | 단계 수 |
|---|---|---|---|
| 1 | 설계 | `CLAUDE.md` + `docs/` 6종 작성 | 10 |
| 2 | 백엔드 | `backend/` FastAPI > API 7개 + 받아쓰기 | 10 |
| 3 | 프론트 | `frontend/` HTML + JS + Tailwind > 화면 4종 > API 연결 | 8 |

## 진행 규칙

- **순서대로만** 진행한다. 앞 단계가 `[x]` 가 되기 전에 다음 단계로 가지 않는다.
- **병렬 금지.** 한 번에 한 단계만 한다.
- **단계별 검증 필수.** 표의 「검증 방법」을 실제로 해 보고 통과해야 `[x]` 로 바꾼다.
- 완료 열은 `[ ]` 로 두고, 진행하면서 `[x]` 로 바꾼다.

### 지시어

| 지시 | 뜻 |
|---|---|
| `backend 진행해` | **Phase 2 전체** (2.1 ~ 2.10) |
| `frontend 진행해` | **Phase 3 전체** (3.1 ~ 3.8) |

## 고정값

- **서버 포트: `8000`** (고정). 프론트도 같은 서버가 같은 오리진으로 제공한다 → `http://localhost:8000`
- **Phase 2 의존성은 아래 8개로 한정.** 이 목록 밖은 추가하지 않는다 (`03-design.md` 3절).
  `fastapi` · `uvicorn` · `sqlalchemy` · `pytest` · `httpx` · `google-genai` · `python-multipart` · `python-dotenv`
- pytest 실행 시 **`httpx2` 설치 권고가 떠도 무시**한다.

## Phase 2 - 백엔드

`backend/` FastAPI > API 7개 + 받아쓰기. 기준 문서: `02-specs.md`

| 단계 | 검증 방법 | 완료 |
|---|---|---|
| 2.1 가상환경 + 의존성 8개 설치 | `pip list` 에 8개가 있고 목록 밖 직접 설치가 없다 | [x] |
| 2.2 앱 뼈대 - `.env` 읽기, 포트 8000, 프론트 정적 제공 | `uvicorn` 을 8000 으로 띄우면 응답한다. 키가 코드에 없다 | [x] |
| 2.3 Meeting 모델 8필드 + SQLite AUTOINCREMENT | 테이블 DDL 에 `AUTOINCREMENT` 가 있다. 지운 id 를 다시 쓰지 않는 테스트 통과 | [x] |
| 2.4 요청 스키마 + 검증 (`extra="forbid"`, 400 핸들러) | 필수 누락 400 · 스펙 외 필드 422 테스트 통과 | [x] |
| 2.5 CRUD - `POST` · `GET` 단건 · `PUT` · `DELETE /api/notes` | 201 · 200 · 200 · 204 · 없는 id 404 테스트 통과. 목록엔 `body` 없음 · 단건엔 있음 | [x] |
| 2.6 목록 검색 - `q` · `from` · `to` | 제목 · 참석자 부분 일치, 본문 미검색, 양끝 포함(`to` 23:59:59) 테스트 통과 | [x] |
| 2.7 세 갈래 구분 (Gemini) | 프롬프트에 기준이 그대로 있다. **실제 Gemini 호출**로 세 갈래가 채워지는 테스트 통과 (호출 사이 1초). 20자 미만은 호출 없이 빈 값 · 실패 시 201 + 빈 값 · 429/503 1회 재시도가 코드에 있다 | [x] |
| 2.8 `POST /api/upload` 받아쓰기 | mp3 · wav 외 415 · 25MB 초과 413 · 외부 실패 502 · 성공 200 테스트 통과 | [x] |
| 2.9 `GET /api/todos` | 필드 `what` · `who` · `when` · `note_id` · `note_title`, 회의 날짜 오래된 순 테스트 통과 | [x] |
| 2.10 전체 테스트 + 실제 호출 | `pytest` 전부 통과. 8000 에서 녹취 파일 하나로 업로드 → 저장 → 세 갈래 확인 | [x] |

`frontend/` `index.html` + `app.js` + Tailwind CDN > 화면 4종 > API 연결.
화면 4종은 **`02-specs.md` 화면 명세**와 **`03-design.md` 표**대로 만든다. 배치는 `docs/화면구성.pdf`.

| 단계 | 검증 방법 | 완료 |
|---|---|---|
| 3.1 뼈대 - 헤더 · 탭 · 테마 토글 (Mac OS 톤) | 8000 에서 열린다. 테마가 시스템 설정으로 시작하고 토글이 새로고침 뒤에도 유지된다 | [x] |
| 3.2 목록 화면 + 검색 (`q` · `from` · `to` · `cards`) | 카드가 보이고, 검색이 `02-specs` 6절대로 걸러진다 | [x] |
| 3.3 넣기 화면 - 업로드 · 붙여넣기 · 저장 | 파일 → `body` 에 받아쓴 본문이 채워지고, 저장하면 `result` 에 세 갈래가 보인다. 구분 실패는 실패로 표시된다 | [x] |
| 3.4 상세 창 - 보기 · 수정 · 삭제 (`modal` · `mTitle`) | 카드를 누르면 열리고, 수정 · 삭제가 새로고침 뒤에도 반영된다 | [x] |
| 3.5 할 일 화면 (`todoBody`) | 담당자 · 기한이 보이고 회의 날짜 오래된 순이다 | [x] |

| 3.8 360px 반응형 + 성공 기준 확인 | 360px 에서 안 깨진다. `01-product.md` 성공 기준 4개를 눈으로 확인 | [x] |
